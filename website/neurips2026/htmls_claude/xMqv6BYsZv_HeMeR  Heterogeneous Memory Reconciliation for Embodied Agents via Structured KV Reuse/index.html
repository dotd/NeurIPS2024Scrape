HeMeR: Heterogeneous Memory Reconciliation for Embodied Agents via Structured KV Reuse

Saehun Chun1, Wonje Choi1, Jinwoo Jang1, Taeyoon Kwack2, Honguk Woo1,2*
1Department of Computer Science and Engineering, Sungkyunkwan University
2Department of Artificial Intelligence, Sungkyunkwan University
{thousae,wjchoi1995,jinustar,njj05043,hwoo}@skku.edu

* Honguk Woo is the corresponding author. 40th Conference on Neural Information Processing Systems (NeurIPS 2026).

Abstract (summary)

Embodied agents combine declarative, procedural, and working memory. Many memory contents stay the same across consecutive decisions. However, existing memory interfaces feed each updated memory context to the foundation model as new input, which forces full KV-cache recomputation. HeMeR tracks the contents of all three memory types, keeps the KV states of unchanged contents, and recomputes only the affected ranges. It is evaluated on ALFWorld, Habitat, and a real robot. In the real-world setting it reaches 83.20% success and cuts per-step time from 2.94 s (MemRL) to 1.87 s.

1 Introduction (summary)

The paper frames heterogeneous memory use as a KV reconciliation problem. It proposes two mechanisms:

  • Chunk-Level KV Reconciliation, which handles declarative and working-memory changes and uses RoPE remapping when chunks shift position.
  • Adapter-Stable KV Reconciliation, which handles procedural LoRA adapter switches.

Headline results:

  • ALFWorld: 71.43% SR at 0.18 s/step, vs. 52.86% at 0.90 s/step for MemRL.
  • Habitat: 76.27% at 1.82 s/step, vs. 61.80% at 2.68 s/step.
  • Real world: 83.20% at 1.87 s/step, vs. 64.28% at 2.94 s/step.

2 Related work (summary)

The paper situates itself among three lines of work:

  • Foundation-model embodied control.
  • Memory-augmented agents, each of which focuses on a single memory role.
  • KV reuse, including prefix caching, CacheBlend, EPIC, and KEEP, along with multi-LoRA serving systems such as S-LoRA, Punica, and LRAgent.

3 Problem formulation

The agent has memory modules

\[\mathcal{M}=\{\mathcal{M}^{dec},\mathcal{M}^{proc},\mathcal{M}^{work}\}\tag{1}\]

Each module retrieves contents at step \(t\):

\[\mathcal{R}^m_t=R^m(o_t,g,h_t)\tag{2}\] \[D_t=\mathcal{R}^{dec}_t,\;P_t=\mathcal{R}^{proc}_t,\;W_t=\mathcal{R}^{work}_t\tag{3}\]

The contents are composed into a memory context, which conditions the action:

\[X_t=\Gamma(D_t,P_t,W_t),\quad a_t\sim F_\theta(\cdot\mid X_t,o_t,g)\tag{4}\]

The goal is a serving policy that trades off task success against inference cost:

\[\Pi^\star=\arg\max_\Pi \mathbb{E}_{\tau\sim\mathcal{D}}\Big[\mathrm{Succ}(\tau;\Pi)-\lambda\sum_{t=1}^T\mathrm{Cost}(\Pi,X_{t-1},X_t)\Big]\tag{5}\]

4 Method (summary)

4.1 Overall Architecture

Each memory content becomes a typed chunk. A schema records its ID, type, role, content, dependencies, position, token span, KV range, and adapter ID.

4.2 Chunk-Level KV Reconciliation

Consecutive contexts are compared to produce a reconciliation plan:

\[\Delta_t=\mathrm{Diff}_{\mathcal{S}}(X_{t-1},X_t)\tag{6}\]

Chunks that only shift position have their cached keys remapped:

\[\tilde{k}_j=R_{\theta(p'_j)}R^{-1}_{\theta(p_j)}k_j\tag{7}\]

4.3 Adapter-Stable KV Reconciliation

HeMeR uses LRAgent-style shared-attention LoRA (rank 8, applied to Q/V, with a shared down-projection). When the adapter changes, the procedural chunk and its dependents are recomputed.

5.3 Analysis

5.4 Ablation

Removing chunk-level reconciliation hurts most (59.40% SR). Removing the schema gives 62.67%, and removing adapter-stable reconciliation gives 64.85%.

6 Conclusion (summary)

Schema-indexed KV reconciliation improves both success and latency. Extending it to multi-agent settings with concurrent memory updates is left as future work.
